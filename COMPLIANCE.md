# Соответствие техническому заданию

Сверка решения с ТЗ «Сервис формирования цифрового признака транспортного средства»
(файл `../7. Фалькон Тех.pdf`). Для каждого требования — где оно выполнено и чем
проверяется.

## §3. Целевые задачи

| требование | статус | где |
|---|---|---|
| Формирование признака из кропа по BBox | выполнено | `POST /embed`; кроп — `reid/dataset.py:_crop_bbox`, поле вокруг рамки `bbox_margin=0.10` |
| Ранжирование галереи по убыванию вероятности | выполнено | `POST /search`, `POST /jobs/batch`; косинусное сходство L2-нормированных векторов |
| Режим предложения кандидатов с отказом | выполнено | `POST /search` → `matched: false` и `refusal_reason`; в `candidates.csv` для отказа строка не пишется |
| Порог обоснован | выполнено | `../EXPERIMENTS.md` §7.2: замеры по двум критериям, таблица рабочих точек, выбран 0.30 |
| Детекция, ОКР номеров и трекинг не требуются | соблюдено | BBox приходит извне, распознавание номеров отсутствует |

## §4. Функциональные требования (этапы обработки)

| этап | статус | где |
|---|---|---|
| Получение: изображение + BBox через API или UI, базовая валидация | выполнено | `api/main.py`: `parse_bbox` (4 числа, w/h > 0), `read_upload` (пустой файл, лимит 25 МБ), `open_image` (битый файл → 422), проверка наличия CSV и колонок |
| Обработка: эмбеддинг фиксированной размерности float32 | выполнено | `api/engine.py:embed_tensors` (пакет `reid` внутри сервиса); 5632-d float32, L2-нормированный |
| Анализ: векторный поиск по мере близости | выполнено | `api/store.py`: косинус через pgvector (`<=>`) либо матмул numpy |
| Результат: топ-N либо пустой ответ при низкой уверенности | выполнено | `SearchResponse`: `candidates` + флаг `accepted` на каждом, `matched` на ответе |

## §6. Архитектура, код и сборка

| требование | статус | где / комментарий |
|---|---|---|
| Микросервисная архитектура: backend инференса, БД, клиентская часть | выполнено | три сервиса в `docker-compose.yml`: `api`, `db`, `ui`; общаются только по сети. Каталог `service/` самодостаточен: код модели (`reid/`), конфиги и веса внутри |
| Backend на Python | выполнено | FastAPI + PyTorch |

| OpenAPI (Swagger) | выполнено | генерируется FastAPI: `/openapi.json` (3.1.0), Swagger UI `/docs`, ReDoc `/redoc`; 9 методов |

| Docker + docker-compose, запуск одной командой | выполнено | `docker compose up --build` поднимает все три сервиса; без Docker — `python service/run_local.py` |
| Открытый неообфусцированный код с комментариями | выполнено | комментарии объясняют причины решений, а не пересказывают код |
| Соответствие документации | выполнено | `README.md` сервиса, `../README.md`, `../EXPERIMENTS.md`, этот файл |

## §9. Критерии оценки — чем закрываем

| критерий | вес | чем закрыт |
|---|---|---|
| Точность на закрытом тесте (mAP) | 45% | mAP@10 **0.894**, Rank-1 0.843, Rank-5 0.967 по эталонному протоколу на репетиции с воспроизведённой структурой теста (`../test_official.py`) |
| Производительность и применимость | 20% | см. §7 выше; разбор по этапам конвейера в `../EXPERIMENTS.md` §9 |
| Инженерное качество | 15% | микросервисы, OpenAPI, СУБД, единый источник кода модели, воспроизводимость через конфиги и `--resume` |
| Корректность режима отказа | 10% | F1 0.598 и TNR при пороге 0.30; обоснование по двум критериям в §7.2 |
| Защита решения | 10% | `../EXPERIMENTS.md`: 10 разделов, включая отрицательные результаты и разбор ограничений |

Учтено, что **совпадения в пределах одной камеры из расчёта исключаются**: наша оценка
воспроизводит junk-фильтрацию организатора, и именно из этого вырос главный выигрыш
в обучении (кросс-камерный triplet, +3.6 pt) — `../EXPERIMENTS.md` §1 и §4.2.

## Что не сделано

**Проверка контейнеров.** `docker-compose.yml` и Dockerfile написаны, но сборка и запуск
контейнеров на машине разработки не выполнялись — Docker-демон не был запущен. Проверено
запуском без Docker через `python service/run_local.py`: backend отвечает на `/health`,
`/openapi.json` и `/docs`, полный цикл (загрузка галереи → поиск → отказ) отрабатывает,
все четыре страницы интерфейса исполняются без исключений, сквозной сценарий поиска
через интерфейс находит верное ТС. Перед сдачей сборку контейнеров нужно прогнать:
`docker compose up --build`.

**pgvector.** Путь PostgreSQL написан по документации pgvector, но выполнялся только
SQLite-бэкенд (интерфейс у них общий, `api/store.py`). При первом запуске compose стоит
убедиться, что `POST /gallery/bulk` отвечает `200` и `GET /gallery/stats` показывает
`backend: postgres+pgvector`.
